2. What is an Algorithm Visualizer?
An algorithm visualizer is an application that demonstrates how an algorithm executes step by step.
Normally, when you execute a sorting algorithm, you only see the final sorted array.
For example:
int[] numbers = {50, 20, 40, 10, 30};
After sorting:
[10, 20, 30, 40, 50]
But you cannot easily see:
Which elements were compared.
Which elements were swapped.
How many operations occurred.
How the algorithm moved through the array.
Why one algorithm is faster than another.
An algorithm visualizer makes these operations visible.

You should implement the following sorting algorithms.
3.1 Bubble Sort
Bubble Sort repeatedly compares adjacent elements and swaps them when they are in the wrong order.
Example:
Initial: [5, 3, 8, 1] Compare 5 and 3 Swap: [3, 5, 8, 1] Compare 5 and 8 No swap: [3, 5, 8, 1] Compare 8 and 1 Swap: [3, 5, 1, 8]
Continue until the array becomes sorted.

3.2 Selection Sort
Selection Sort repeatedly finds the smallest element in the unsorted portion and places it at the next correct position.
Example:
[50, 20, 40, 10] Find minimum → 10 Swap with first element [10, 20, 40, 50]
Complexity:
Best: \(O(n^2)\).
Average: \(O(n^2)\).
Worst: \(O(n^2)\).
Auxiliary space: \(O(1)\).
3.3 Insertion Sort
Insertion Sort builds a sorted portion one element at a time.
It works similarly to arranging playing cards in your hand.
Complexity:
Best: \(O(n)\).
Average: \(O(n^2)\).
Worst: \(O(n^2)\).
Auxiliary space: \(O(1)\).
3.4 Merge Sort
Merge Sort uses Divide and Conquer.
Its main process:
Divide the array into smaller halves.
Recursively sort each half.
Merge the sorted portions.
Example:
[8, 3, 6, 2] / \ [8, 3] [6, 2] / \ / \ [8] [3] [6] [2] \ / \ / [3, 8] [2, 6] \ / [2, 3, 6, 8]
Complexity:
Best: \(O(n\log n)\).
Average: \(O(n\log n)\).
Worst: \(O(n\log n)\).
Auxiliary space: \(O(n)\) for a conventional array implementation.
3.5 Quick Sort
Quick Sort chooses a pivot and partitions elements into smaller and larger groups.
Complexity:
Average: \(O(n\log n)\).
Worst: \(O(n^2)\).
Auxiliary space: depends on recursion depth and implementation.
3.6 Heap Sort
Heap Sort builds a heap and repeatedly extracts the largest element.
Complexity:
Best: \(O(n\log n)\).
Average: \(O(n\log n)\).
Worst: \(O(n\log n)\).
Auxiliary space: \(O(1)\) for an in-place implementation, excluding implementation details such as recursion if used.

4. Visualize Searching Algorithms
Implement two primary searching methods.
4.1 Linear Search
Linear Search checks elements one by one.
public static int linearSearch(int[] arr, int target) { for (int i = 0; i < arr.length; i++) { if (arr[i] == target) { return i; } } return -1; }
Complexity:
\[ O(n) \]
The visualizer highlights every position checked.
4.2 Binary Search
Binary Search works on sorted arrays.
It repeatedly divides the search space into two halves.
public static int binarySearch(int[] arr, int target) { int left = 0; int right = arr.length - 1; while (left <= right) { int mid = left + (right - left) / 2; if (arr[mid] == target) { return mid; } if (arr[mid] < target) { left = mid + 1; } else { right = mid - 1; } } return -1; }
Complexity:
\[ O(\log n) \]
The visualizer should show:
Left pointer.
Middle pointer.
Right pointer.
Current comparison.
Remaining search range.
It should also explain why the array must be sorted.

6. Visualize Graphs
Graph visualization is one of the most valuable parts of this capstone.
A graph contains:
Vertices (nodes).
Edges (connections).
Optional edge weights.
6.1 Breadth-First Search
BFS uses a queue.
It explores nodes level by level.
Example:
A / \ B C / \ \ D E F
Starting at A:
BFS: A → B → C → D → E → F
Your visualizer should show:
Current node.
Queue contents.
Visited nodes.
Newly discovered neighbours.
6.2 Depth-First Search
DFS explores as far as possible along one path before backtracking.
It can use recursion or an explicit stack.
A possible traversal for the same graph:
DFS: A → B → D → E → C → F
The exact traversal depends on neighbour ordering.
6.3 Dijkstra's shortest path
Dijkstra's algorithm finds shortest distances from a source to other vertices in a graph with non-negative edge weights.
Example:
Weighted graph example
Illustrative weighted graph. Edge weights are example values.
The algorithm maintains the currently known shortest distance to each node.
It repeatedly processes the unvisited node with the smallest tentative distance, commonly using a PriorityQueue.
Important steps:
Initialize source distance to zero.
Initialize other distances to infinity.
Remove the nearest current node from the priority queue.
Relax its outgoing edges.
Update distances and predecessor information.
Continue until the queue is empty or the target is finalized.
For adjacency lists and a binary heap, a typical complexity is:
\[ O((V+E)\log V) \]
The visualizer should show the distance table and the current shortest path.
6.4 Prim's Minimum Spanning Tree
Prim's algorithm builds a minimum spanning tree by adding the cheapest edge connecting the existing tree to a new vertex.
It is useful for understanding minimum-cost network connections.
For example:
Connecting cities.
Designing network infrastructure.
Connecting computer systems.
With an adjacency list and binary heap, a common complexity is:
\[ O(E\log V) \]
Your application should highlight:
Selected edge.
Current tree.
Remaining candidate edges.
Total tree weight.
For disconnected graphs, explain that the algorithm must be restarted for each component if you want a minimum spanning forest.

10.2 Implement a Dynamic Array
The class should maintain:
An internal array.
Current size.
Current capacity.
Example:
public class DynamicArray<T> { private Object[] elements; private int size; public DynamicArray() { elements = new Object[10]; size = 0; } public void add(T value) { if (size == elements.length) { resize(); } elements[size++] = value; } private void resize() { Object[] newArray = new Object[elements.length * 2]; System.arraycopy( elements, 0, newArray, 0, size ); elements = newArray; } public int size() { return size; } }
This example shows the core idea. A finished implementation must also provide get, set, remove, bounds validation, and appropriate handling of nulls.
Your visualizer should show how capacity changes when the array becomes full.

11. Project Architecture
11.1 What is software architecture?
Software architecture is the high-level organization of a system.
It describes:
Major components.
Responsibilities.
Communication between components.
Data flow.
External dependencies.
Security boundaries.
Without architecture, code can become difficult to maintain as the project grows.
11.2 Layered architecture
For a Java application, you can use this structure:
Layered architecture
Presentation Layer
UI, controllers, user interactions
Service Layer
Business rules and application workflows
Domain / Algorithm Layer
Java models, algorithms, data structures
Infrastructure Layer
Database, file storage, external services, execution workers
Not every project needs all four layers. The objective is to separate responsibilities rather than introduce unnecessary complexity.
11.3 Separation of responsibilities
For example, a StudentService should handle student-related business rules.
A StudentRepository should handle persistence.
A controller should handle incoming requests or user interactions.
Do not place all application logic inside one giant Main.java file.

15. Java Implementation Standards

15.1 Object-Oriented Programming
Use:
Classes and objects.
Encapsulation.
Inheritance when appropriate.
Polymorphism.
Abstraction.
Interfaces.
Composition.
For example:
public interface SortingAlgorithm { String getName(); void sort(int[] numbers); }
You can create separate classes:
public class BubbleSort implements SortingAlgorithm { @Override public String getName() { return "Bubble Sort"; } @Override public void sort(int[] numbers) { for (int i = 0; i < numbers.length - 1; i++) { for (int j = 0; j < numbers.length - i - 1; j++) { if (numbers[j] > numbers[j + 1]) { int temp = numbers[j]; numbers[j] = numbers[j + 1]; numbers[j + 1] = temp; } } } } }
This allows your application to work with different sorting algorithms through one interface.
15.2 Generics
Use generics when implementing reusable data structures.
public class Stack<T> { private final List<T> elements = new ArrayList<>(); public void push(T value) { elements.add(value); } public T pop() { if (elements.isEmpty()) { throw new NoSuchElementException("Stack is empty"); } return elements.remove(elements.size() - 1); } }
This allows the same stack implementation to store Integer, String, or custom objects.

Performance benchmarking measures how your project behaves under specific conditions.
For example, compare:

18.2 A sorting benchmark
You may initially measure elapsed time using:
long start = System.nanoTime(); algorithm.sort(numbers); long end = System.nanoTime(); long duration = end - start; System.out.println("Time: " + duration + " ns");
This is suitable for a basic demonstration but not enough for reliable performance conclusions.
For serious benchmarking:
Use JMH.
Warm up the JVM.
Run repeated measurement iterations.
Use equivalent input data.
Prevent dead-code elimination.
Report averages and variation.
Include hardware and JDK details.
18.3 Complexity versus actual performance
Suppose you compare Bubble Sort and Merge Sort.
For a tiny input, Bubble Sort might be faster because its implementation is simple and its overhead is low.
For a sufficiently large input, Merge Sort's \(O(n\log n)\) behaviour generally becomes much more favourable.
This teaches an important principle:
Big-O predicts scalability, while benchmarking measures actual behaviour on a specific system and workload.
